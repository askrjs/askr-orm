# 0.5.0 ORM API decisions

Status: implementation candidate; API issue #53 remains open for the complete 0.5.0 packed-package and generated website review. PostgreSQL generation/validation also remains blocked by [#55](https://github.com/askrjs/askr-orm/issues/55).

The published 0.4.0 declarations expose 132 entrypoint/name pairs. The curated contract exposes 78: 68 root names, one CLI bridge, seven PostgreSQL names and two SQLite names. There are 54 removed named exports, plus the removed `sql.key` member. No compatibility shims are provided.

## Export-map decisions

| Key              | Decision | Supported owner                                                                               |
| ---------------- | -------- | --------------------------------------------------------------------------------------------- |
| `.`              | KEEP     | Application schema, SQL expressions, database factory and explicit adapter/type contracts.    |
| `./postgres`     | KEEP     | PostgreSQL driver and dialect-specific column declarations; optional peers remain lazy.       |
| `./sqlite`       | KEEP     | Node SQLite driver; root/SQLite imports work without PostgreSQL peers.                        |
| `./tooling`      | KEEP     | Single runDatabaseCli bridge used by askr-cli, with implementation moved to a private module. |
| `./package.json` | KEEP     | askr-cli resolves the declared tooling import via package metadata.                           |

The runtime and declaration contract is frozen in `tests/public-contract.json`. Private source modules and dist paths are denied by the export map. Type-only ColumnBuilder remains usable as an annotation and cannot be constructed through the root.

## Nested SQL member decision

`sql.identifier`, `sql.literal` and `sql.unsafe` are the canonical paths. `sql.key` is removed: defineQuery owns named application queries and generated metadata. Lower placeholder rewriting utilities stay private and their inert-text regression tests remain.

## Consumer audit

The 0.4.x compiler inventory found only the type fixture importing createDatabaseClient from the package. It now uses defineDatabase/open with an explicit custom driver. Source-level unit/integration tests retain direct imports of their private implementation helpers. The benchmark now opens through defineDatabase; its timed CRUD/prepared/bulk workloads and budgets are unchanged.

Additional string/dynamic consumers were inspected: askr-cli reads package.json and invokes runDatabaseCli, and ORM generated source imports GeneratedDatabaseArtifact. Both are retained. No sibling application/template imports of the removed root/tooling names or sql.key were found in the reviewed source snapshots. Website API generation remains pending the complete 0.5.0 candidate set.

## Reusable typed declarations

```ts
import {
  numeric,
  eq,
  type ColumnBuilder,
  type Expression,
  type SqlFragment,
  type Codec,
} from "@askrjs/orm";
const money = (): ColumnBuilder<string> => numeric(10, 2);
const equals = <T>(left: Expression<T>, value: T): SqlFragment<boolean> => eq(left, value);
const caseFold: Codec<string, string> = {
  name: "case-fold",
  encode: (value) => value.toLowerCase(),
  decode: (value) => value,
};
```

Use type-only imports for adapter contracts, options and inference. Install pg/pg-query-stream for PostgreSQL use and @types/pg for TypeScript consumers. The packed check verifies the documented minimum peers 8.23.0/4.17.0 with a normal install, strict TypeScript 6/7 declaration checking, exact runtime/declaration names, all 54 removed imports, private subpath denial, and SQLite migration/rollback recovery.
